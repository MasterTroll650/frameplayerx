# Developing FramePlayer

## Layout

| Crate | Purpose |
|---|---|
| `fp-core` | Shared types: formats and detection, view settings, sources, playback status |
| `fp-ffmpeg-sys` | Bindings to the bundled FFmpeg 7.1 (per-arch, generated by `tools/gen-ffmpeg-bindings.sh`) |
| `fp-media` | Demux/decode (V4L2 hardware, dav1d), A/V clock, audio out (ALSA), subtitles, thumbnails |
| `fp-render` | Vulkan renderer: projection shader for every format, egui panels, quads |
| `fp-xr` | OpenXR session (direct runtime loading), input, haptic pulses, passthrough |
| `fp-library` | SQLite library: scanning, metadata worker, thumbnails, search, history |
| `fp-sources` | Local, HTTP, WebDAV, DLNA, DeoVR/HereSphere and SMB sources |
| `fp-haptics` | Funscript parsing, sync engine, TCode/Buttplug/Handy devices |
| `fp-remote` | DeoVR remote API and the phone web remote |
| `fp-updater` | Signed update manifests, safe install/rollback; `fp-release` tool |
| `frameplayer` | The app: XR loop, UI, wiring |
| `frameplayer-install` | PC-side installer over SSH |
| `frame-probe` | Milestone 0 platform probe |

## Build and test

```
tools/build-ffmpeg.sh x86_64 aarch64     # once: FFmpeg + dav1d into third_party/
export LD_LIBRARY_PATH=$PWD/third_party/ffmpeg/x86_64/lib
cargo test --workspace                   # GPU tests use any Vulkan device (lavapipe is fine)
tools/package.sh                         # release zip + manifests for the Frame in dist/
```

Needs Rust 1.89+, meson 1.12 (1.3 cannot use zig's linker; versions between are untested), ninja,
nasm, pkg-config, zig (`pip install
ziglang`) and `cargo-zigbuild`. Binaries target glibc 2.28.

## Running without a headset

`--preview` renders offscreen with a simulated head and right controller,
driven by a script, and saves screenshots (see `crates/frameplayer/src/preview.rs`
for the commands):

```
cat > /tmp/demo.fps <<'X'
wait 2
point main 0.24 0.04     # Watch history tab
click
shot history
open ~/Videos/clip_180_LR.mp4
wait-playing 20
shot playing
X
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json \
  cargo run -p frameplayer -- --preview /tmp/shots --script /tmp/demo.fps
```

### On this computer with Monado

`tools/local-xr.sh` runs FramePlayer against [Monado](https://monado.freedesktop.org),
the open-source OpenXR runtime, so a change can be tried without building
and installing on the Frame. Monado shows both eyes in a desktop window and
fakes the headset and controllers from the keyboard and mouse. It works on
Ubuntu and Debian, and on Windows in Ubuntu under WSL2 (WSLg shows the
windows and plays the sound; Vulkan runs on llvmpipe there, so expect a low
frame rate).

```
tools/local-xr.sh setup                 # once: Monado, build tools, FFmpeg
tools/local-xr.sh run                   # Monado + FramePlayer
tools/local-xr.sh run ~/Videos/clip.mp4 # ...opening a video
tools/local-xr.sh headless --exit-after 10 clip.mp4   # no window: smoke test
tools/local-xr.sh preview /tmp/shots    # every screen as PNGs (ui-preview.sh)
```

Click into Monado's debug window (*Monado!*) to drive it: the keyboard and
mouse move the headset, or the left or right controller while left Ctrl or
left Alt is held. WASD/QE move, the arrow keys or a right-button drag turn,
a left click is the trigger, Shift goes faster; its *Qwerty › Help* tab
lists every key. The controllers present themselves as Khronos simple
controllers (select and menu), which FramePlayer binds. The window with the
eyes opens at 1600×900 (`LOCAL_XR_WINDOW=1280x720` for another size) and
can be resized; under WSL it is Monado's X11 window, as its Wayland one
stays black there. Monado's own log is
in `/tmp/monado-service.log`; `-v` gives FramePlayer's debug log. Under WSL
the Linux build goes to `~/.cache/frameplayer-target`, away from the
Windows `target/`. The eyes are 150% of the fake headset's 640×720 by
default; `XRT_COMPOSITOR_SCALE_PERCENTAGE=200 tools/local-xr.sh run` is
sharper, `=60` smoother on a software renderer.

By hand, with Monado's simulated headset and no window:

```
XRT_COMPOSITOR_NULL=1 SIMULATED_ENABLE=1 monado-service &
XR_RUNTIME_JSON=/usr/share/openxr/1/openxr_monado.json \
  cargo run -p frameplayer -- --exit-after 10 video.mp4
```

## Releasing

1. Once: `fp-release keygen`, paste the printed public key into
   `crates/fp-updater/src/lib.rs` (`RELEASE_PUBLIC_KEY`), and store the
   whole `.key` file as the `FP_RELEASE_KEY` repository secret. Keep the key
   offline otherwise.
2. Stable: push (or merge) to `main`. Beta: run the `ci` workflow on any
   other branch from the Actions tab (Run workflow). CI calculates the
   version, stamps it into `crates/frameplayer/Cargo.toml`, builds,
   packages, signs `manifest.json` and publishes the GitHub release with
   the zip, `manifest.json(.sig)` and `framedrop.json`.

   - `main` gets the next stable `X.Y.Z` from the conventional commits
     since the last stable tag (`git cliff --bumped-version`): a breaking
     change (`feat!:`, `BREAKING CHANGE:`) bumps X, a `feat` bumps Y,
     anything else bumps Z. Beta tags don't count. With no stable tag yet
     it is `v0.4.0` (`initial_tag` in `cliff.toml`).
   - Other branches get that version as `X.Y.Z-beta.N` (N one above the
     highest existing beta of it, and always above the latest stable),
     published as a GitHub pre-release that never becomes "latest".
     FramePlayer offers it on the Beta update channel only.
   - Pushing a `vX.Y.Z` or `vX.Y.Z-anything` tag releases exactly that
     version (pre-release if it has a `-`).

Until a key exists, in-app updates and `frameplayer-install` without
`--zip` refuse to install (they never accept unsigned manifests).
